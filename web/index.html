why

A browser shaped like vim, not chrome.

01 — INPUT

Modal browsing

Normal/insert/visual modes. Real motions, real text objects, real ex commands.

02 — LINKS

Hint mode

Press f, every link gets a label. Type the label, you're there. No mouse needed.

03 — RENDER

Rust + CEF

Chromium rendering, native window, native fonts. No Electron, no JVM, no webview wrapper.

04 — GPU

GPU-accelerated

Compositing on the GPU. Smooth scroll, fast paint, low-latency input.

05 — INTERACTION

Mouse + keyboard

Both, always. Power users get keys. Everyone else gets mice. Neither is second-class.

06 — PRIVACY

Zero telemetry

No analytics. No phone-home. Your browsing, your business.

status

__VERSION__

Live in __VERSION__: multi-tab browsing; popup windows (window.open, OAuth) render in dedicated buffr windows with read-only address bars and preserve window.opener; target="_blank" and Ctrl+click open in tabs; two-finger horizontal swipe navigates browser history; vim modal engine wired for page-mode dispatch and insert-mode text editing; history / bookmarks / downloads / permissions / zoom data layers persisted to SQLite.

Added since 0.1.0: per-monitor HiDPI scaling; ASCII loading animation across reload + navigation; single-instance launching with URL forwarding (open a link → new tab in the existing window); native Wayland clipboard via hjkl-clipboard 0.4; AUR package; expanded release matrix (Linux x86_64 / aarch64, macOS arm64, Windows x64 / arm64).

Grab a binary from github.com/kryptic-sh/buffr/releases. Modal layer shared with the hjkl editor.
